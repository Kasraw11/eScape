## How Data Currently Flows

```text
City of Melbourne Open Data API
-> backend ingestion script
-> SQLAlchemy session using DATABASE_URL
-> Aiven MySQL table
-> backend route/refuge APIs
-> frontend UI
```

The application does not read local CSV files at runtime. The frontend calls the backend API, and the backend reads from Aiven using `DATABASE_URL`.

## Important Integration Finding

The repository still has two database approaches that need to be aligned:

1. `database/schema.sql` is a planned MySQL schema.
2. `backend/app/models/*` is the operational schema currently used by the backend and ingestion scripts.

Because the frontend/backend route planner uses SQLAlchemy models, the integration test used backend models as the operational source of truth. `database/schema.sql` should be updated before the team treats it as the production DDL.

Known mismatches include:

- Backend uses `sensor_location.location_name`; planned schema uses `sensor_location.location`.
- Backend uses `historical_pedestrian_count.sensor_id`; planned schema uses `historical_pedestrian_count.location_id`.
- Backend uses `realtime_pedestrian_count.sensor_id` and `sensed_at`; planned schema uses `location_id`, `sensing_datetime`, `sensing_date`, and `sensing_time`.
- Backend models include `journey_request`, `route_segment`, `sensory_prediction`, richer POI metadata, and feedback tables.
- Planned schema has better transport stop natural-key handling with `(stop_id, mode)` than the current backend model.

## Live Data Refresh Strategy

The current scripts fetch live data only when they are run. For the assignment demo this is enough, but for a shared/live application the team should automate ingestion.

Recommended approach:

1. Short-term/demo:
   - Run the scripts manually before testing.
   - Use `--max-records 1000` or `--max-records 5000` depending on time and Aiven limits.

2. Team integration:
   - Add a scheduled job every 15 minutes using GitHub Actions, Render cron, Railway, or another hosted scheduler.
   - Store `DATABASE_URL` as a secret in the scheduler, not in Git.

3. Production-like flow:
   - Import sensor locations daily or weekly.
   - Import recent pedestrian counts every 5-15 minutes.
   - Run prediction recalculation after each live ingestion.
   - Keep historical monthly data as the baseline source for predictions.
